# 표현을 줄인 바닥 적용 기록

사용자 실제 적용 요청과 “바닥이 너무 산만해졌어 / 표현을 더 보수적으로” 피드백을 반영한 최신 적용이다. 앞선 볼트·큰 홈·은색 벗겨짐이 많았던 안을 대체했다.

## 실제 리소스

- `assets/textures/handpaint_blue/floor_hearthstone.png`: `../hearthstone-conservative-floor-20261006/floor_4m_final.png` 바이트 동일 복사, 1254² RGB. SHA256 `95f43d022a1e0e6c91f4650dc11aab8c9dfdb2f73c9582865ea2c7776f2dfd58`.
- 기존 UID와 고품질 BPTC·미프맵 임포트 설정 유지. 원화 자체 색 후처리·새 재그림 없음.
- 기본 바닥은 기존 직접 샘플링 분기에서 4m 월드 XZ 투영한다. 네 판에 볼트와 큰 홈이 없고, 작은 흠집 두 곳만 드물게 반복한다. 추가 절차 마모·붓 샘플 혼합 없음.
- `blue_handpaint.gd`의 `FLOOR_LIFT`를 1.18로 맞추었다. 선형 색 배율이며 PNG 픽셀을 수정하지 않는다. 바닥 파괴 조각은 기존 복제 경로로 상속한다.
- 벽·조명·모델·UV·판정은 이 적용에서 변경하지 않았다. `--bgfloor=previous`는 최초 적용 직전 붓 혼합 바닥으로 비교하며, `--bgpaint=old`는 최초 청보라 구현 전 옵션이다.

## 톤 근거

[game_comparison.png](game_comparison.png) / [tone_validation.json](tone_validation.json) / [check_tone.py](check_tone.py).

실제 `main.tscn` 봇 실행의 두 시점(물리 프레임90/120)을 일시정지해 바닥 재질만 전환했다. 같은 카메라·배치·조명이다. 마젠타 단색 셰이더로 보이는 바닥을 마스크 처리하고 물체 경계2px를 제외했다. 선택 픽셀은 각각821,135/591,459개다. 비교 촬영에서만 유체를 끄고, 별도 기본 설정 봇 실행은 유체·감염을 유지했다.

| 측정 | 명도 HSV V 차(%p) | 채도 HSV S 차(%p) | 평균 RGB 색상 차(도) | sRGB 가중 명도 변화 |
| --- | ---: | ---: | ---: | ---: |
| 실제 게임90프레임 | −0.393 | +0.653 | −0.949 | −1.057% |
| 실제 게임120프레임 | −0.367 | +0.684 | −0.937 | −1.073% |
| 조명 제외 실제 셰이더4m ALBEDO | +0.282 | +0.169 | −0.747 | +0.852% |

기존 청보라 톤은 가깝게 유지됐다. 장면의 개별 위치 명암은 그림이 달라 차이가 있을 수 있지만, 같은 화면에서의 평균색 변화는 작다. 게임 카메라에서 볼트·큰 홈이 없는 차분한 표면과 가는 줄눈, 그림자와 기존 바닥 데칼이 함께 보이는 것을 육안 확인했다. 4m 반복이므로 전 맵의 모든 판이 고유한 텍스처는 아니다.

## 검증과 복구 자료

고정 Godot4.7.2 표준 Forward+ 및 `tools/godot.ps1` 사용. PowerShell에서 게임 인자 구분자는 문자열 `'--'`로 넘겨 실제 user args를 전달했다. 비교 스크립트는 `scene.player.bot`을 assert하며 완료 로그에 실제 게임 시간을 찍는다.

`import.log`, `game_compare.log`, `flat_before/after.log`, `bot_main.log`, `bot_run.log`, `tests.log`에 최종 실행을 저장한다. 최종 검증 상태는 `validation.json`을 확인한다. `infest_previous.log`는 앞서 실패했던 감염 밀어내기 검사를 직전 바닥으로 실행해 PASS한 추가 근거다(테스트 수정 없음).

최종 결과: 임포트·실제 비교 렌더·기본 본편/섹터 런 30게임초 봇 모두 종료0·ERROR/SCRIPT ERROR0. 전체47검사는 종료1, 45개 통과·2개 실패(`diagonal_cutin_check`: 기존 누락 보이스7항목, `lancaster_boss_check`: 발 접지1항목). 후자는 새 바닥 재실행과 기존 바닥 재실행에서 모두 PASS했으며 최초 전체 실행의 실패는 기록에 남겼다. 이 추가 보스 검사의 종료 정리 때 ObjectDB3개 경고도 로그에 보존했다. 바닥·BrawlLook·GroundBreak 검사는 모두 PASS, `final_audit.py`의 실제 리소스/톤/런타임 검증도 PASS했다. 전체가 무조건 녹색이라고 보고하지 않는다.

`before/`에는 이번 작업 직전 PNG/임포트/설정 코드를 보관했다. 과거 전체 코드를 통째로 덮어 다른 작업을 취소하지 말고 필요한 차이만 복구한다. 이전 시안·취소된 적용의 자료 보존. 다른 작업자의 많은 변경 파일이 있으므로 이번 두 리소스/설정 변경 외에 임의 복구하지 않는다. 커밋·푸시 없음.
