보라 양갈래 정비사 — 고개 들기·머리 넘기기·윙크

완성 GIF: hairflip_wink.gif (512×512, 12프레임, 한 동작 1000ms)
게임용 원본: hairflip_atlas.png (RGBA 2048×1536, 4열×3행, 셀512×512)
개별 PNG: frames/frame_00.png ~ frame_11.png
편집 파일: hairflip_wink.aseprite
적용 규격: animation.json / 정렬 내역: registration.json

동작 순서
0~220ms 고개를 들고 눈을 감기 시작
220~450ms 고개를 뒤로 젖히며 머리카락을 한 번 넘김
450~600ms 정면 복귀, 머리카락 잔흔들림
600~1000ms 윙크와 미소 유지
반복 미리보기에서는 마지막 윙크에서 시작 자세로 돌아가는 컷이 있음.
게임에서는 단발 재생(loop=false) 후 마지막 프레임을 유지하거나 컷인을 퇴장시킨다. 왕복/ping-pong 재생 금지.

피벗 계약 — 모든 프레임 동일
좌표 원점: 캔버스 왼쪽 위, 오른쪽+x/아래+y.
캔버스:512×512. 피벗: (256,409.6), 정규화(0.50,0.80).
정렬용 허리 버클 중심: (256,450). 머리카락/얼굴 외곽으로 정렬하지 않는다.
각 프레임은 같은 배율1.14로 확대하고 버클을 기준으로 평행이동했다. 프레임별 배율 변경/자동 크롭/회전 없음.
원화 시트는1448×1086 생성 결과이며, 고해상도 원화를 축소한512px가 아니다. 확대 사용 시 이 해상도 한계를 고려한다.
생성 원화의 작은 옷 주름/몸통 그림 변화는 남아 있다. 고정된 캔버스·피벗과 원화 모든 픽셀의 일치는 서로 다르다.

Godot 후속 적용값 (이번 작업에서 본편 코드는 변경하지 않음)
- 기존 DiagonalDockingCutin의 ART=1254를 그대로 쓰지 말고 이 에셋에서는512로 설정한다.
- ANCHOR_UV=(0.5,0.8), HAIR_UV는 이 에셋 여백에 맞춰 약0.137을 사용한다.
- Sprite2D/AnimatedSprite2D centered=false, local position=(-256,-409.6).
  부모를 사선 기준점 O+sT에 둔다. 부모에만 공통 화면 배율을 적용한다.
- TextureRect 방식은 position=-pivot_px*공통배율, size=(512,512)*공통배율.
- 프레임 교체 시 position/scale을 다시 계산하거나 프레임별 alpha bbox로 크롭하지 않는다.
- 아틀라스는 animation.json의512×512 region을 사용한다. 반투명 가장자리 보존을 위해 PNG를 게임용으로 사용한다.
- 사선 하단 마스크는 기존 화면 기준 셰이더에서 적용한다. PNG 자체에는 사선 자르기를 굽지 않았다.
- 기존 원화용 UV 모핑 영역은 새 몸 위치와 다르므로 재조정하거나 끈다. 스프라이트시트 전체 UV로 모핑하지 않는다.
- 재생은 animation.json의 누적시간으로 프레임을 고른다. 렌더 한 번당 한 프레임씩 전진시키지 않는다.
- 컷인 시작과 동시에 재생하면600ms부터 윙크,1000ms에 끝. 기존900ms 퇴장을 유지하면 마지막100ms는 퇴장과 겹치므로 얼굴 가독성을 보고 부모 체류 시간을 조절한다.
- GIF에는 PNG의 연속 알파/색을 모두 담을 수 없으므로 GIF는 동작 확인용, RGBA PNG가 적용 원본이다.

검증
- GIF를 다시 열어12프레임/512×512/총1000ms 확인.
- PNG12장 동일 캔버스, 모든 그림이 캔버스 경계 안에 있음(가장자리 알파 픽셀0).
- 버클 위치에 적용한 변환의 수치 오차0. 원화의 모든 몸통 픽셀이 동일하다고 주장하지 않는다.
- 전체 시트와 고개를 든 프레임/머리 넘김/최종 윙크 육안 확인.
- validation.json에 프레임별 경계/시간/SHA256 기록. 본편 적용·엔진 테스트는 아직 하지 않음.

재생성
pack.ps1: 생성된 source_sheet.png의 분리된 인물12개를 알파 연결 영역으로 추출하고 피벗 정렬. 옆 셀로 넘어간 머리끝도 인물 연결 영역을 따라 보존.
assemble.lua: Aseprite batch에서 PNG12장을 타임라인으로 묶고 GIF/aseprite 저장.
validate.ps1: 결과 파일을 다시 읽어 검사.
원화 생성: 내장 imagegen 사용. prompt_v1.txt/prompt_v2.txt에 실제 프롬프트 보존.
시각 입력: purple-worker-cheerful.png(같은 인물 편집 대상), 최초 캐릭터25/31/38/43 PNG(그림체만).
Aseprite API 참고: https://www.aseprite.org/api/sprite / https://www.aseprite.org/api/frame
게임 코드 수정·커밋·푸시 없음. 기존 파일 보존.
