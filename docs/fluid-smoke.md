# 유체 연기 (나비에-스토크스) · 기체 청소 기믹

바닥에 깐 2D 유체 격자 하나로 연기를 푼다. Main 계열 씬 전부에 붙고(보스 전장 제외), 필드에는 **안개**(분위기, 청소 대상 아님)와
**독가스**(청소 대상)가 가끔 생긴다. 연기 자체는 판정이 없다(연기 구역 `SmokeZone` 의 은신 판정과는 별개).

| 파일 | 하는 일 |
|---|---|
| `scripts/presentation/fluid_smoke.gd` (`FluidSmoke`) | 격자 계산(GPU 컴퓨트) · 방출기 모으기 · GPU 합계 비동기 읽기 · 쉬기 |
| `scripts/presentation/fluid_smoke_fx.gd` (`FluidSmokeFX`) | 그리기: 카메라 컴포지터 효과, 절반 해상도 광선 행진 + 깊이 보며 올려 붙이기 |
| `scripts/presentation/fluid_field.gd` (`FluidField`) | 씬에 깔기 · 안개 둑 / 독가스 세트 배치 · 청소 판정 · 도트 다단 흡수 |

기존 코드 변경: `main.gd` 의 `FluidField.attach(self)` 한 줄 · `distortion_fx.gd` 의 `burst` 첫 줄(`FluidSmoke.blast`) · 로비 목록 한 줄.

## 기체 청소 기믹

- **안개 둑**: 26초 동안(시험장은 계속) 옅은 안개를 뿜다 그친다. 감쇠 0.10/초라 그치면 흩어진다. 빨려도 **게이지 없음** — 청소 대상 아님.
- **독가스 세트**: 구름 2~3개를 0.55초 동안 **한 번만** 만든다(계속 뿜지 않음). 독가스는 **감쇠 0** — 저절로 사라지지 않는다.
  바닥에 초록 빛(OmniLight)이 남은 양만큼 비친다. 생길 때 "독가스 누출" 팝업.
- **빨아들이기**: Space 청소 질주(반경 5m) · Z 직접 청소(앞쪽 3.6m)가 흡입 방출기를 낸다. GPU 압력 빼기 단계에서 **빨아 먹은 독가스 양**을 작업 묶음별로 합쳐
  (shared memory 합 → atomicAdd 고정소수) 매 프레임 `buffer_get_data_async` 로 읽어 온다.
- **정화 판정**: 만든 직후 늘어난 독가스 합으로 세트 양 `m0` 를 재고, 빨아 먹은 양을 가장 가까운 세트에 몫으로 단다.
  남은 몫(격자 전체 독가스 합으로 흐름 손실 보정) < 7% 면 **정화 완료**: 남은 찌꺼기는 터뜨려 지우고 "독가스 정화!" · 고리 · 반짝 · 드론 `player_cleaned` +1 (다른 오염처럼 청소 1회).
- **도트 다단 흡수**: 세트 값 = 구름 × 14 게이지. 빨아 먹은 비율만큼 쌓아 두었다가 **0.05초마다 1씩** 게이지에 넣는다 → "+1" 이 연달아 튀고 '틱' 소리가 점점 높아진다
  (밀려 쌓이면 간격이 줄어 따라잡는다). 묶음이 끝나면 "흡입 +N". 보통 오염은 다 치운 순간 한 번에 "+N" 이라 손맛이 다르다.

| 적 몸 | `PUSH` | 지나가며 휘젓는다 |
| 2단 대시 휠윈드 | `SWIRL` (바깥으로 흩뿌림) | 몸 둘레로 감기며 퍼진다 |
| Q 합체 휠윈드 | `SWIRL` (안쪽으로 감김, 더 크고 셈) | 회오리 |

| 폭발·내려찍기·무거운 검·미사일 | `Distortion.burst` → `FluidSmoke.blast` → `RADIAL` (0.32초, `haze` 가 있으면 그을음) | 가운데가 비고 둘레에 연기가 쌓인다 |
| 통풍구(시험장) · 안개 둑 · 독가스 생성 | `RADIAL`(연기 추가 + 약한 퍼짐) + 느린 `SWIRL` | 뭉게뭉게 차오른다 |

## 계산 (`FluidSmoke`)

Stable Fluids(Jos Stam)를 GPU 컴퓨트 셰이더(주 RenderingDevice, `call_on_render_thread`)에서 푼다.
상태 (속도 x, 속도 z, -, 그을음) `rgba32f` ×2 + 스타일 염료(채널 4개) `rgba32f` ×2, 압력 `r32f` ×2, 발산, 막힌 칸(맵의 `is_blocked_cell`),
화면용 A (높이 단면, 결 세기, 결 속도, 밀도) · B (스타일 비율) `rgba16f`, 방출기 버퍼(앞 vec4 4개 = 스타일 높이·결·결 속도·감쇠, 뒤로 방출기 64개), 합계 버퍼 uint×4.

한 프레임(최대 dt 1/30): ① **이동** semi-Lagrangian(벽 칸을 뺀 쌍선형) · 감쇠 · 약한 확산(벽 칸 제외) · **압축/팽창 항** `ρ ← ρ·exp(-∇·v dt)`
② **소용돌이 보강** ③ **발산** ④ **압력 야코비** 20(짝수) ⑤ **압력 빼기 → 방출기 → 화면용 A·B 굽기 → 합계**.

- **방출기는 압력을 뺀 "뒤"에 넣는다** — 폭발·가르기·흡입은 발산이 있는 흐름이라 압력 단계를 거치면 사라진다.
- **압축/팽창 항이 없으면 고르게 퍼진 연기는 아무리 불어도 고른 채로 남는다**(semi-Lagrangian 은 비압축 전제). 단, 압력 반복이 못다 지운 작은 발산(|∇·v| < 1.2/초)은
  빼고 건다 — 그대로 두면 가만히 있는 독가스가 10초에 +13% 불었다(빼고 나서 +3%).
- 벽 칸을 섞으면 벽 가까이서 연기가 0 과 섞여 줄어든다(감쇠 0 인 독가스가 3초에 13% 사라짐) → 이동 · 확산 모두 벽 칸을 빼고 무게를 다시 맞춘다.
- **쉬기**: 격자 합이 0 에 가깝고 연기를 넣는 방출기가 0.5초 넘게 없으면 계산·그리기를 건너뛴다 (방 탐색은 대부분 이 상태 — 비용 0).

## 그리기 (`FluidSmokeFX`, 최적화 1 · 2 · 3)

**기본값 (사용자 확정 2026-10-06, 모든 씬)**: 화면 `view_mode = 1` **밀도**(행진 없이 광선이 닿는 바닥 자리의 밀도 × 스타일 색을 옅게 덮음) · 품질 **FULL**(원 해상도).
밀도 화면은 높이장 행진을 하지 않으므로 걸음 수(40)는 0(연기) 화면으로 바꿀 때만 쓰인다. 시험장 F8 로 0 연기(높이장 행진) ↔ 1 밀도, Shift+F8 로 품질.
1080p 측정(그리기): 통풍구 0.35ms · 화면 가득 0.46ms (연기 화면 FULL 은 0.85 / 2.41ms), 방 탐색 독가스+안개 계산 0.31 · 그리기 0.24ms.

카메라의 `Compositor` 에 끼운 `CompositorEffect`(투명 패스 뒤, MSAA 해소된 색 · 깊이). 장면 데이터 UBO(Godot 4.7 은 `mat4` 투영 2개 + **행 우선 `mat3x4`** 뷰 2개)로
화소의 장면 점을 월드로 되돌려 카메라→장면 점 광선을 만든다(투영 부호 관례에 기대지 않는다).

1. **절반 해상도** (`Quality.HIGH`): 1단계는 (W/2)×(H/2) 에서 행진해 미리 곱한 색 + 투명도와 그 화소 깊이를 적고,
   2단계는 원 해상도에서 둘레 4칸을 쌍선형 × 깊이 닮은 정도로 섞어 장면 색에 덮는다 (캐릭터 윤곽에서 연기가 번지지 않게).
2. **품질 단계** `FluidSmoke.quality`: LOW = 절반 24걸음 · 반씩 좁히기 3회, HIGH = 절반 40걸음 · 5회, FULL = 원 해상도 40걸음(**기본**). 시험장 **Shift+F8**.
3. **행진 한 걸음 = 텍스처 한 번**: 높이 계산에 쓰는 값(높이 단면 · 결 세기 · 결 속도 · 밀도)을 계산 쪽에서 A 한 장에 미리 굽고,
   스타일 비율 B 는 닿은 곳 색칠에서만 읽는다 (예전: 한 걸음마다 밀도 + 염료 두 장).

## 부하 (RTX 3060 · 고정 Godot 4.7.2 Forward+)

`_capture/fluid_perf_probe.gd [-- --res=1920x1080]` → `output/fluid-smoke-20261005/perf_<해상도>.json`. 계산 · 그리기는 GPU 타임스탬프(180프레임 평균),
뷰포트 전체 시간은 프레임마다 ±0.3ms 흔들려 비교에서 뺐다.

**그리기 (최적화 전후)**

| 그리기 GPU | 1280×800 통풍구 | 1280×800 화면 가득 | 1920×1080 통풍구 | 1920×1080 화면 가득 |
|---|---|---|---|---|
| 2차(원 해상도 공간 셰이더, 걸음마다 두 장 읽기 — 뷰포트 증가분) | +0.39 | +1.13 | +0.77 | +2.50 |
| FULL (원 해상도, 한 장 읽기) | 0.41 | 1.32 | 0.85 | 2.41 |

| LOW (절반, 24걸음) | 0.16 | 0.36 | 0.22 | 0.52 |

**계산 · 그 밖**

| | 값 |
|---|---|
| 계산 (시험장 176×136) | 0.10~0.13ms |
| 계산 (방 탐색 맵 전체 384×368) | 0.21ms |
| 방 탐색, 연기 없음 (쉬기) | 계산 0 · 그리기 0 |
| 방 탐색, 독가스 세트 + 안개 | 계산 0.21 · 그리기 0.18 (1080p 0.32) |
| CPU (방출기 모으기 + 명령 기록) | 0.13~0.22ms |
| GPU 메모리 | 시험장 2.2MB · 방 탐색 12.9~13.5MB |

**해석**

- **① 절반 해상도가 결정적**: 그리기 −55~70% (1080p 화면 가득 2.41 → 0.84ms). 화소가 1/4 이라도 올려 붙이기(원 해상도 한 번)가 있어 1/4 까지는 아니다.
- **② 품질 LOW** 는 화면 가득일 때 효과가 크다(1080p 0.84 → 0.52ms). 보통 장면에선 빈 곳 버리기가 대부분을 거르므로 차이가 작다.
- **③ 한 장 읽기**는 원 해상도끼리 견주면 차이가 작다(1080p 화면 가득 2.50 → 2.41ms 정도) — 걸음당 읽기보다 잡음 함수 · 반씩 좁히기 · 법선 계산 몫이 크다.
  대신 염료 B 를 행진에서 빼면서 스타일이 늘어도 행진 비용이 늘지 않는다.
- **계산은 거의 공짜**이고, 방 탐색처럼 넓은 맵은 연기가 없을 땐 **쉬어서 0** 이다. 60fps 예산 16.7ms 기준으로 독가스가 있는 1080p 필드에서 계산 + 그리기 약 0.5ms (3%).
