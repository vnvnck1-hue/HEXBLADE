# 성능 · 끊김(렉) 점검과 최적화

기체(파트너 드론)·감염·유체 연기·벌레 적·연출 프리셋이 늘어나며 생긴 프레임 끊김을 측정으로 찾아 고친 기록.
새 기능을 넣을 때 아래 "규칙"을 지키고, 의심되면 측정 도구로 전·후를 비교한다.

## 측정 도구

| 도구 | 하는 일 |
|---|---|
| `_capture/frame_probe.gd` | 씬을 자동 플레이로 돌리며 (vsync 끔) 프레임 시간 분포 · 25ms 넘는 끊김(HITCH) · 그 프레임에 생긴 노드 종류 · 그리기 호출 수를 찍는다. 기능을 끈 실행(`--drone=off` 등)과 비교하면 기능별 비용이 나온다 |
| `_capture/spawn_probe.gd` | 벌레 4종을 여러 번 만들어 `new` / `_ready` / 첫 프레임 시간을 잰다 |
| `_capture/burst_probe.gd` | 감염 포낭 체액 터짐을 1·4·10개 한꺼번에 내고 비용을 잰다 |
| `_capture/leak_probe.gd` | (기존) 씬 재로딩 누수 |

```
powershell -File tools\godot.ps1 wait -s res://_capture/frame_probe.gd -- --scene=res://scenes/main.tscn --bot --dronebot --seed=4 --seconds=9999 --probe-seconds=40 --tag=base
```

Main 은 `--bot` 이면 `--seconds=`(기본 20초) 뒤 스스로 끝내므로 `--seconds=9999` 를 같이 주고, 측정 길이는 `--probe-seconds=` 로 준다
(안 주면 Main 이 20초에 먼저 끝내 버려 결과 줄이 안 찍힌다 — 충돌처럼 보이지만 정상 종료).

`_capture/phys_profile.gd` 는 물리 틱 하나를 [그 밖 / Main / 플레이어 / 드론 / 적] 구간으로 나눠 오래 걸린 틱만 찍는다.

**측정 주의 — 로그를 파일로 받으면 `print()` 가 느려진다.** PowerShell 을 거쳐 파일로 리다이렉트하면 `print` 한 줄이 평균 2ms(최대 7ms) 걸려
게임 로그(ROOM_CLEAR · BUG_ROOM …)가 찍히는 틱마다 가짜 끊김이 생긴다. 파이프(`| grep`)로 받으면 0.02ms. 끊김을 잴 때는 파이프로 받는다.

## 결과 (방 탐색 벌레 아레나 `main.tscn`, `--bot --dronebot --seed=4`, 40초, RTX 3070 · 1280×800, vsync 끔)

| | 평균 | p99 | 최악 | 25ms 넘는 끊김 |
|---|---|---|---|---|
| 손대기 전 | 8.2ms | 17.8ms | 120ms | 26회 |
| 손댄 뒤 | 5.4~5.9ms | 12~13ms | 44ms | 3회 |

평상시 프레임은 손대기 전에도 120fps 이상이었다 — 체감 렉은 대부분 **처음 한 번 하는 준비**와 **한 프레임에 몰리는 노드 생성**이었다.

| 항목 | 전 | 후 |
|---|---|---|
| 촘퍼 등장 (`_ready`) | 90ms (매번) | 0.5ms |
| 개미 · 공벌레 등장 | 20ms (매번) | 0.5ms |
| 첫 애벌레 · 첫 공벌레 | 38ms · 12ms | 씬 로딩 때 |
| 첫 포낭 터짐 | 32ms | 1ms |
| 첫 교전(첫 명중 · 총구 · 폭발 · 잔상) | 40~60ms | 씬 로딩 때 |
| 첫 가스통 폭발 (그을음 무늬) | 30ms | 씬 로딩 때 |
| 첫 최대 레이저 (빔 메시·셰이더) | 14ms | 씬 로딩 때 |
| 첫 패링 예고 별빛 (벌레 덮치기) | 29ms | 씬 로딩 때 |
| 첫 부스터 기류 · 첫 바닥 흔적 | 20ms · 18ms | 씬 로딩 때 |
| 포낭 연쇄 터짐 한 프레임 노드 | 500여 개 | 방울 90 · 얼룩 36 상한 |

기능별 평상시 비용(A/B, 같은 seed): 감염 약 1ms(대부분 터짐 연출 자체) · 드론 약 0.3ms · 유체 연기 약 0.3ms · 나머지(배경 톤 · 설비 · 독가스)는 측정 오차 안.
게임은 스크립트(CPU) 쪽이 주로 시간을 쓴다 (물리 틱 평균: 플레이어 0.6 · 적 0.5 · 그 밖 0.4 · 드론 0.2ms).

남은 큰 틱(10~25ms, 1분에 몇 번): 플레이어의 큰 기술 순간 — 충전 레이저 발사(임팩트 프레임 정지가 가린다) · 도약 내려찍기 시작 · 기 모으기 돌진.

## 원인과 고친 것

**처음 한 번의 준비를 전투 중에 하던 것** (셰이더 코드를 메인 스레드에서 컴파일 · GDScript 로 텍스처를 한 점씩 굽기 · 효과음 합성 · GLB 다시 읽기)
- `BugEnemy.model_scene` · `warm` · `warm_rigs` — 벌레 GLB 를 정적으로 붙잡고(마지막 개체가 사라지면 풀려 매번 디스크에서 다시 읽었다), 벌레 아레나는 씬 시작 때 백그라운드로 읽는다. 애벌레 스키닝 · 공벌레 말림표 · 벌레 효과음도 씬 시작 때.
- `FxWarm` (`scripts/presentation/fx_warm.gd`, `Main._ready` 한 줄) — 씬을 불러온 직후 플레이어 발밑 25m 아래(시야 안이라 실제로 그려짐, 바닥에 가려 안 보임)에서 타격 버스트 · 총구 · 착탄 · 불꽃 · 폭발 · 기류 · 패링 별빛 · 최대 레이저 · 잔상 · 바닥 파괴 재질을 한 번 내고, 피해 숫자 · 말풍선 글리프를 굽고, 컷인 층을 만든다. 그동안 효과음은 끈다.
- `Infestation._ready` — 체액 셰이더 · 액체 시트 텍스처 · 효과음. `DockingVoice.warm` — 합체 보이스 버스.

**짧은 연출을 매번 노드로 만들고 지우던 것**
- 잔상 `FX.afterimage` → `GhostPool` (`scripts/presentation/ghost_pool.gd`): 예전엔 한 번에 홀더 + 파츠 약 30개 + 머티리얼 복제 + 트윈. 이제 노드 재사용 · 머티리얼 하나 · 흐려짐은 전역 셰이더 값 `ghost_clock` 으로 GPU 가 계산.
- 총 연출 `ToonGunFX.spawn` — 총알 한 발에 15~25개씩 만들던 쿼드를 `_free` 에 모아 재사용.
- 불꽃·착탄 파티클 `FX.sparks` · `GunFX._spray` → `FX.burst_particles` 풀 (`amount_ratio` 로 개수만 바꿔 버퍼를 다시 잡지 않음). 흐르는 씬(추격 보스전)은 예전 방식.
- 감염 체액 `InfestSplash` — 한 물리 프레임에 방울 90 · 얼룩 36 개까지.

**쉬어도 될 때 계속 일하던 것**
- 조명 풀(플레이어 주변만 밝게): 배경 재질마다 매 프레임 두 값씩 넣던 것 → 전역 셰이더 값 `bl_pool` 하나 (`project.godot` `[shader_globals]`). 재질은 `pool_use` 만 가진다.
- `BrawlLook` 의 `node_added` 훅: 셰이더 · 투명 재질인 이펙트 노드는 지연 변환 호출을 만들지 않는다.
- 맵 전체의 연기 구역 · 레일 롤러 · 가스통 경고등 · 드론 오염(꿀렁임·거품): `Cull.far` (플레이어 26m 밖) 이면 쉰다.
- 감염 둥지: 멈춘 혹은 변환·셰이더 값을 다시 쓰지 않고, 카메라 48m 밖은 그리지 않는다(그림자 포함, `visibility_range_end`).
- 드론 흡입 줄기 10개 · 콤보 미터 · 합체 보이스(덕킹 끝나면) · 말풍선(스프링이 멈추면 다시 그리지 않음).
- 바닥 파괴 찌그러짐: 매 프레임 → 30Hz(흔적 20Hz), 한 프레임 8개까지.
- 칼 궤적: 표본이 촘촘하면(휠윈드 · TEMPEST) 곡선 보간 분할을 하지 않는다.

**글꼴 글리프를 계속 새로 굽던 것**
- 피해 숫자(`DamageLog`) · 합체 글자(`GattaiFX`): 팝·열기마다 정수 크기·외곽선이 바뀌어 크기마다 글리프를 구웠다 → 고정 크기 몇 개로 굽고 변환 배율로 키운다.

**그 밖**: HUD·`Striker` 의 그룹 조회를 `Enemy.live()` 로.

## 새 기능을 넣을 때의 규칙

1. **전투 중에 `load()` 하지 않는다.** 마지막 사용자가 사라지면 리소스가 풀려 다음 `load()` 가 디스크에서 다시 읽는다
   (촘퍼 GLB 75ms). 정적 변수로 붙잡거나 씬 시작 때 미리 읽는다 (`BugEnemy.model_scene` · `warm`).
2. **처음 한 번만 하는 무거운 준비(효과음 합성 · 스키닝 · 셰이더 · 글꼴)는 씬 시작 때 한다.**
   `FxWarm`(전투 연출) · `BugEnemy.warm_rigs` · `Infestation._ready` · `DockingVoice.warm` 참고.
3. **짧은 연출을 매번 노드로 만들고 지우지 않는다.** 자주 나오면 풀(`GhostPool` · `ToonGunFX._free` · `FX.burst_particles`)을 쓴다.
   한 프레임에 수백 개가 생길 수 있는 연출은 프레임당 상한을 둔다 (`InfestSplash.FRAME_DROPS`).
4. **글꼴 크기를 매 프레임 바꾸지 않는다.** 크기마다 글리프를 새로 굽는다. 고정 크기로 그리고 `draw_set_transform` 배율로 키운다.
5. **많은 재질에 같은 값을 매 프레임 넣지 않는다.** 전역 셰이더 값(`project.godot` `[shader_globals]` — `bl_pool` · `ghost_clock`) 하나로 넘긴다.
6. **맵 전체에 깔리는 꾸밈은 멀리서 쉰다.** `Cull.far(위치)` (플레이어에서 26m 밖 = 화면 밖) 이면 갱신을 건너뛴다. 판정에는 쓰지 않는다.
7. **멈춘 것은 다시 쓰지 않는다.** 스프링이 쉬면 변환·셰이더 값 쓰기를 건너뛰고(`InfestNest` 혹), 쉬는 UI 는 다시 그리지 않는다(`ComboMeter` · `SpeechBubble`).
8. **그룹 조회는 `Enemy.live(get_tree())`** (프레임당 한 번만 배열을 만든다).
