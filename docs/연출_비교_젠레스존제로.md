# 헥스 블레이드 vs 젠레스 존 제로 — 게임 연출 · 기술 스택 비교 분석

작성일: 2026-09-30 · 대상: 현재 `main` 작업 트리(Godot 프로젝트 "Neon Arena (Claude)" / 헥스 블레이드)

> **한 줄 요약**
> 우리 게임은 **"코드로 합성한 절차적 연출을 실시간 게임 루프 안에서 짧게 터뜨리는"** 방식이고,
> 젠레스 존 제로(이하 ZZZ)는 **"아티스트가 손으로 만든 애니메이션·이펙트·컷인을, 게임 판정에 맞춰 정해진 순간에 재생하는"** 방식이다.
> 타격감의 문법(히트스탑·임팩트 프레임·패링 섬광)은 이미 상당히 닮았지만, **캐릭터 연기·컷신·카메라 컷·2D 그래픽 레이어**는 구조적으로 비어 있다.

### 근거와 한계

- 우리 쪽: 저장소 코드와 문서를 직접 읽고, API 사용 횟수는 `scripts/**/*.gd` 를 grep 해 셌다.
- ZZZ 쪽: 공개 가이드와 커뮤니티 자료, 플레이 경험으로 알려진 사실을 기준으로 했다. HoYoverse는 ZZZ의 내부 파이프라인을 자세히 공개하지 않았으므로 **(추정)** 이라고 적은 항목은 공개된 결과물과 커뮤니티 리버스 엔지니어링으로 짐작한 내용이다.

## 2. 게임적 연출: 무엇이 다른가

### 2.1 이미 비슷한 것 — "타격 순간의 문법"

우리 게임은 ZZZ가 쓰는 전투 순간 연출 어휘를 상당수 이미 갖고 있다.

| 기법 | 우리 구현 | ZZZ 대응 |
|---|---|---|
| 히트스탑 | `Engine.time_scale` 조절(19회 사용), 카메라·흔들림도 함께 정지 (`main.gd`, `camera_rig.gd`) | 타격마다 짧은 정지 |
| 흑백 임팩트 프레임 | `impact_frame.gd`: 밝기를 문턱값으로 잘라 흑/백만 남기고 다음 프레임 반전, 총구 소실점 집중선 | 체인·궁극기·패링 순간의 흑백/반전 컷 |
| 패링 예고 섬광 | 금빛 십자 별빛 + 기체 전신 금빛 발광, 알림 후 정확히 0.4초 뒤 명중 (`Parry.TRAVEL`) | 금빛 섬광 = 대응 가능 공격 |
| 패링 성공 슬로 | 2F 흑백 → 2F 정지 → 0.3배 슬로 → 0.11초 뒤 복귀, 줌인 0.87배 | 지원 난입 순간 정지 + 슬로 |
| 퍼펙트 회피 | 대시 끝 타이밍 2단 대시 → 무지개 잔상 + PERFECT | 퍼펙트 회피 → 회피 반격 / Vital View 슬로 |
| 콤보 이징 | 준비 ease-out cubic, 스윙 ease-out expo(첫 프레임에 거의 다 뻗음), 여운 ease-out back (`docs/sword-combo.md`) | 예비 동작 → 몇 프레임 만에 폭발하는 스윙 → 긴 여운 |
| 잔상 | `saber_trail.gd`: 수명 약 2프레임의 초승달 리본, 한 틱 사이 자세를 최대 12번 보간 | 스미어/무기 궤적 이펙트 |

**결론:** "한 번 칠 때의 느낌"은 이미 ZZZ 계열 문법 위에 있다. 차이는 그 **위층**에 있다.

### 2.2 구조적으로 다른 것

#### ① 캐릭터가 "연기"를 한다 vs 기체가 "반응"한다
- ZZZ: 모든 행동이 캐릭터의 성격을 드러내는 **연기**다. 대기 모션, 교체 등장 포즈, 기술마다 다른 몸짓, 표정이 있다. 연출의 주인공은 캐릭터다.
- 우리: 로봇은 스프링 기울기·찌그러짐·숨쉬기로 **물리적으로 반응**한다(`player.gd`). 절차적이라 입력에 즉각 반응하고 튜닝이 쉽지만, 포즈에 "의도"와 "개성"을 싣기 어렵다.
- 영향: 연출의 초점이 캐릭터가 아니라 **이펙트와 화면 효과**에 모인다. 현재 빛·섬광·화면 필터가 풍부한 이유이기도 하다.

#### ② 파티 교체가 연출 장치다
- ZZZ의 핵심 연출 셋은 교체와 묶여 있다.
  - **지원 공격(Assist)**: 금빛 섬광 공격에 교체 버튼 → 다음 캐릭터가 난입해 막거나(Defensive) 피하고(Evasive) 반격한다.
  - **체인 공격(Chain Attack)**: 적이 기절(Daze)한 상태에서 강공격 → 시간이 멈추고 좌/우 캐릭터 선택 컷인 → 교체 캐릭터의 연계기. 일반 몹 1회, 정예 2회, 보스 3회.
  - **궁극기**: 전용 시네마틱 카메라와 컷신.
- 우리는 단일 기체라서 같은 순간에 **"누가 들어오는가"라는 기대감과 선택**이 없다. 패링은 "같은 기체의 반격"으로 끝난다.

#### ③ 금빛/붉은 섬광의 "두 가지 문법"
- ZZZ: 금빛 = 교체로 받아칠 수 있음, 붉은 섬광 = 반드시 회피. 플레이어가 색 하나로 **대응 방법**을 읽는다.
- 우리: 금빛(패링 가능) 예고는 있지만, "패링 불가·회피 전용" 공격을 알리는 별도 색 규칙은 없다. 붉은 예고는 경고 띠·조준선(`laser_warning.gd`)처럼 **범위 예고**로 쓰인다. 색이 "어디를 피하라"는 뜻이지 "어떻게 대응하라"는 뜻이 아니다.

#### ④ 게임을 멈추는 연출(컷신·컷인)이 있는가
- ZZZ: 체인 공격 선택 화면, 궁극기 컷신처럼 **게임 흐름을 의도적으로 끊고 보여 주는 순간**이 있다. 이 순간은 카메라 컷, 캐릭터 클로즈업, 배경 단색 처리, 2D 그래픽 레이어가 한꺼번에 들어간다.
- 우리: 모든 연출이 쿼터뷰 카메라 그대로, 수 프레임에서 0.5초 안에 끝난다(`camera_rig.gd` `CINE_END := 0.45`). 설계 원칙("전투 속도를 끊지 않게 짧다", `parry.gd`)이 명확하다. 가장 길게 멈추는 연출은 궁극기 락온(0.18배 슬로, 실제 시간 최대 2초)이다.
- 이것은 **결함이 아니라 방향의 차이**다. 쿼터뷰 탄막 슈터에서 3인칭 컷신은 판독성을 해친다. 다만 보스 격파·궁극기처럼 드문 순간에 한정된 "정지 연출"을 넣을 여지는 있다.

#### ⑤ 카메라 언어
- ZZZ: 추적 카메라가 기본이고, 기술마다 **각도·거리·컷 전환**이 바뀐다. 카메라가 연출의 일부로 편집된다.
- 우리: 한 대의 쿼터뷰 카메라를 **파라미터로** 흔든다 — 추적 속도, 이동 선행, 기울기, FOV 펀치, 격파 지점 끌림, 렌즈 배럴 왜곡·색수차(`presentation/lens_fx.gd`). 컷 전환은 없다.

#### ⑥ 2D 그래픽 레이어
- ZZZ: 만화 칸 분할, 거대한 타이포 효과음, 스티커형 UI, 모션 코믹 스토리 등 **2D 레이어가 3D 위에 적극적으로 얹힌다**. 도시 스트리트 컬처와 레트로 CRT TV 미감이 전체 아트 방향을 묶는다.
- 우리: 2D 레이어는 HUD, 콤보 팝업, 배너 메시지, 집중선 정도다. README 방침대로 패링 성공에서도 **글자 UI 없이** 섬광선만 쓴다. 아트 방향은 "어두운 남색 + 네온 발광 + 로우폴리"로 일관되지만, 브랜드처럼 읽히는 그래픽 언어는 아직 없다.

#### ⑦ 사운드와 음악
- ZZZ: 음악이 전투 강도에 따라 바뀌고, 캐릭터 음성이 기술을 알린다. 사운드가 연출의 절반을 맡는다.
- 우리: 효과음을 **런타임에 수식으로 합성**한다(`sfx.gd` `_synth()`: 사각파·톱니파·노이즈·주파수 스윕). 에셋이 필요 없고 수치로 튜닝할 수 있지만, 음색 폭이 좁고 음악과 음성이 없다. 16채널 풀, 믹서 버스 없음.

## 3. 기술 스택 비교

### 3.1 스택 표

| 레이어 | 헥스 블레이드 | 젠레스 존 제로 |
|---|---|---|
| 엔진 | **Godot 4.x** (`config/features` 4.7, 실행기 4.6.3), Forward+ (Vulkan) | **Unity** 기반, HoYoverse 사내 커스텀 렌더링 (Genshin → Star Rail → ZZZ로 이어진 자체 셰이더 계보) |

| 플랫폼 | Windows PC | PC · 모바일(iOS/Android) · PS5 · Xbox — 다중 플랫폼 스케일링 필요 |
| 에셋 | **외부 에셋 거의 없음.** 모델·이펙트·효과음을 모두 코드로 생성 (`.glb` 2회, `.png` 5회 참조뿐) | 대규모 아트 에셋 파이프라인(DCC 툴 → 엔진 임포트) |
| 모델링 | `build.gd`: 박스 파츠 조합 + 관절 노드. `scripts/modeling/`에 레퍼런스 메크 스튜디오 | DCC(Maya/3ds Max/Blender류)에서 제작한 스키닝 캐릭터, 얼굴 전용 노멀·SDF 맵 (추정) |

| 외곽선 | **화면 공간 후처리**: 깊이·노멀 버퍼 경계 검출(`toon_outline.gd`), 러프니스 0 파츠 제외 | **메시 기반 외곽선**(인버티드 헐/정점 확장)으로 선 굵기·색을 부위별로 제어 (추정, 애니풍 게임 표준) |

### 3.2 핵심 기술 차이 5가지

1. **"데이터로 만든 연출" vs "코드로 만든 연출"**
   ZZZ의 연출은 에셋(애니메이션 클립, VFX 프리팹, 타임라인)이고, 엔지니어는 그것을 재생하는 틀을 만든다. 우리 연출은 **함수**다. 수치를 바꿔 즉시 튜닝할 수 있고 에셋 관리가 없다는 강점이 있지만, 아티스트가 코드를 읽지 않고 손대기 어렵다.

2. **골격 애니메이션의 부재**
   `Skeleton3D`·`AnimationPlayer`를 쓰지 않는다. ZZZ식 캐릭터 연기(과장 포즈, 스미어 프레임, 표정)는 사실상 골격 애니메이션과 키 편집 도구 없이는 만들 수 없다. 반대로 우리의 스프링·트윈 기반 절차 애니메이션은 입력 반응성, 타격 반동, 개체 수가 많을 때 유리하다.

3. **외곽선 방식**
   우리 외곽선은 화면 공간 1패스라 **모든 오브젝트에 일관**되게 적용되고 비용이 고정이다. 대신 부위별 선 굵기·색 제어, 원근에 따른 굵기 변화 같은 애니풍의 "손맛"은 어렵다. ZZZ는 메시 외곽선 + 정점 색으로 부위마다 조절한다(추정).

4. **시간 제어의 범위**
   우리는 `Engine.time_scale` 하나로 **세계 전체**를 멈추고 늦춘다. UI·임팩트 프레임은 실제 시간(ms)이나 `set_ignore_time_scale(true)`로 따로 돈다. ZZZ의 체인 공격·궁극기처럼 "세계는 멈추고 한 캐릭터만 움직이는" 연출에는 **개체별 시간 척도**(로컬 time scale)가 필요하다. 지금 구조로는 모든 노드가 같은 `dt`를 받는다.

5. **플랫폼 스케일링**
   ZZZ는 모바일부터 콘솔까지 같은 연출을 돌리므로 LOD·셰이더 변형·이펙트 품질 단계를 갖춘다(추정). 우리는 PC 한 대를 기준으로 만들었다. `OmniLight3D` 순간 조명 34곳과 풀스크린 캔버스 셰이더 여러 장은 모바일로 옮길 때 비용 문제가 먼저 나올 곳이다.

## 4. 우리의 강점 (유지할 것)

- **판독성 우선의 짧은 연출.** 쿼터뷰 탄막에서는 0.5초 넘게 화면을 가리면 판정 정보가 사라진다. 현재의 "2F 정지 + 몇 F 슬로" 문법은 장르에 맞다.
- **판정과 연출의 분리.** `impact_frame.gd`, `toon_outline.gd`, `presentation/*` 파일마다 "판정과 무관"이라고 명시하고, 연출 전용 모듈(`scripts/presentation/`)이 이미 있다. ZZZ식 연출을 추가할 때 그대로 확장할 기반이다.
- **정확한 타이밍 계약.** 패링 공격은 "알림 후 정확히 0.4초 뒤 명중"으로 고정되어 있다. ZZZ가 섬광 규칙으로 신뢰를 주는 것과 같은 원리다.
- **튜닝 속도.** 상수 몇 개(`EARLY`, `LATE`, `CINE_ZOOM`, 이징 종류)로 느낌을 바로 바꾼다.
- **에셋 없는 일관성.** 모든 것이 코드라 색·톤이 `Pal` 팔레트 하나로 묶인다.

## 5. ZZZ 수준으로 가려면 필요한 것 (우선순위 제안)

| 순위 | 항목 | 이유 | 비용 |
|---|---|---|---|
| 1 | **섬광 색 규칙 2종화**: 금빛 = 패링, 붉은빛 = 회피 전용 | 코드만으로 가능, 전투 판독성 즉시 향상 | 낮음 |
| 2 | **개체별 시간 척도** (`local_time_scale` 계층) | 체인·궁극기류 "세계 정지 + 주인공만 움직임" 연출의 전제 | 중간 (전 개체 `dt` 경로 수정) |
| 3 | **연출 시퀀서**: 카메라·트윈·FX·사운드 키를 한 곳에 적는 데이터 형식 (Godot `AnimationPlayer`의 메서드 트랙이나 자체 리소스) | 연출을 함수에서 데이터로 옮겨 아티스트가 편집 가능하게 | 중간 |
| 4 | **드문 순간의 정지 연출**: 보스 격파·궁극기에 한정한 카메라 컷, 단색 배경, 2D 컷인 레이어 | ZZZ의 "쇼 타임" 순간. 드물게 써야 판독성과 공존 | 중간 |
| 5 | **2D 그래픽 언어**: 타격 타이포, 컷인 프레임, UI 모션 | 아트 방향의 정체성. 지금은 네온 톤만 있음 | 중간 (아트 필요) |
| 6 | **사운드 파이프라인**: 음악 + 버스/믹서 + 녹음 효과음 병행 | 합성음은 프로토타입엔 좋지만 음색 폭 한계 | 중간~높음 |
| 7 | **골격 애니메이션 도입**: 플레이어 기체를 스키닝 모델 + `AnimationTree`로, 절차 스프링은 가산 레이어로 유지 | 캐릭터 "연기"의 전제. 가장 큰 구조 변경 | 높음 |
| 8 | (선택) 캐릭터 교체 | ZZZ 연출의 핵심이지만 게임 디자인 결정이 먼저. 현재 기획서는 "로봇 1종" | 기획 판단 |
